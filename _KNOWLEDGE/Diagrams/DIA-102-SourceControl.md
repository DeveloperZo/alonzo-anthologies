# DIA-102: Where the work lives
## Snapshot
- **Diagram file:** `_KNOWLEDGE/Diagrams/DIA-102-SourceControl.svg`
- **Theme:** Where the work is kept, and the one road a change takes off Zo's computer
- **Primary audience takeaway:** There is one road: from Zo's computer, send the changes up to the online copy. Everything else on the picture is left over.

## What The Diagram Shows
On the left is Zo's computer (the working copy). It holds the work: every page, picture and program. New work exists only there until it is sent. It also holds the secrets folder (`_ENV`), with a key to the publisher account. That folder stays on the computer and is never sent up.

One arrow leaves Zo's computer: send the changes up (`git push`). It lands in the online copy (GitHub), which is public. Inside the online copy is the main copy (the `main` branch), the version the live site is made from. A short arrow on the right says the publisher takes over from there, which is the subject of DIA-103.

A note under the arrow says what happens before sending: Zo checks by hand that no password is going along, and nothing else checks.

The dashed frame at the bottom holds the two leftovers. The old shelf (GitLab, archived) held the work for a few hours and was closed on 2026-10-14; nothing goes there. The old duplicate site (`zo-garden`) still gets every change made to the main copy, until it is retired.

The picture is generated by `gen_site_102_103.py` in this folder. Do not edit the SVG by hand.

## How To Read It
1. Start in the left frame: the work is on Zo's computer, and so is the secrets folder.
2. Follow the one blue arrow to the main copy inside the online copy.
3. Read the note under the arrow: the only check before sending is done by hand.
4. Follow the dashed grey arrow down to the leftovers. One is closed, one is still being fed.
5. The arrow on the far right hands over to DIA-103.
