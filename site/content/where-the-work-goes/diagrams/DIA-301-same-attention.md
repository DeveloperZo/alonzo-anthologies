# DIA-301: The Same Attention, Spent Three Ways
## Snapshot
- **Diagram file:** `site/content/where-the-work-goes/diagrams/DIA-301-same-attention.svg`
- **Theme:** Function over form in software delivery practices, shown through code review
- **Primary audience takeaway:** A team's attention is a fixed budget. When the number of changes multiplies, keeping the form of a practice (review everything) loses its function (catch what can hurt), and the same budget can be spent a different way.

## What The Diagram Shows
Three rows of bars. Each bar is one change, and its height is the attention that change gets. The total bar area is the same in every row, so the three rows cost the team the same.

The first row is the time before: six changes, each one read. The second row is now, with the same ritual: forty-eight changes, every one reviewed, each given a sliver. The third row is one way to respond: forty-two changes get a stamp, and six get nearly the depth the six in the first row had. It is labelled as one path of many.

Claim sentence: the reader should see that the rubber stamp and the selective review cost the same attention, and equal-area bars show it because the eye can compare the thin band in the second row with the six tall bars in the third and see that nothing was added.

## Elements And Flow
- **Components:** three rows of bars on a common left edge and a common scale. Rust bars are changes that get real attention. Grey bars are changes that get a sliver or a stamp.
- **Relationships:** bar area is attention. Row 1 is 6 bars at 120 units. Row 2 is 48 bars at 15 units. Row 3 is 42 bars at 3 units and 6 bars at 99 units. Each row totals 8,640 square units at a bar width of 12.
- **Notable labels or metrics:** the counts (6 and 48, and 6 deep reviews of 48) are illustrative and the diagram says so. They are not measurements. The essay's sourced figure for the growth in output is a vendor report of twice as many code changes (source 2); the diagram does not use it.

## How To Read It
1. Read the first row as the baseline: a few changes, each read properly.
2. Read the second row as the same attention spread over eight times as many changes.
3. Compare the second row with the third. The third spends the same total on six changes and stamps the rest.
4. Read the label on the third row: it is one possible allocation, not a prescription.

## Delivery Relevance
The essay argues that when a machine makes the doing cheap, the work moves to saying what is wanted and finding out whether it was delivered. This diagram shows what that asks of a practice the reader already has. Review was a form that happened to serve its function while volume was low. At higher volume the two come apart, and the team has to choose which one to keep. The same picture holds for specifications, tests and release checks.

Drawing tradition: a small-multiples bar chart, drawn to true area. It is a plain chart and not an engraved plate. Three plates drawn for this essay were rejected on 2026-11-10 as ornament that restated the prose.

What it leaves out: how a team decides which changes carry risk, who does the deep reviews, and every other way of spending the budget (automated checks, pairing, smaller changes, review by a second model).
